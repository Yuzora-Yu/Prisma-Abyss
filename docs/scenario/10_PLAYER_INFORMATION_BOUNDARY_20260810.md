# 10_PLAYER_INFORMATION_BOUNDARY_20260810

## Purpose

2026-08-10 の制作指示を、今後のシナリオ・イベント・UI実装で守るための内部基準として整理する。
これはプレイヤーへ表示する文章ではない。

ゲームは、状態を正しく伝達するだけのアプリではない。
操作、失敗、偶然、見落とし、勘違い、発見、あとから意味が変わる記憶も含めて体験になる。
そのため「理解できるよう全部説明する」ことを品質とはみなさない。

## Player-facing boundary

### 1. 実装理由を本文へ出さない

次の情報は、原則としてプレイヤー向け会話・地の文へ直接書かない。

- storyStep / subStep / flag / route / phase などの進行管理
- 一時パーティ、所持品隔離、EXP倍率、LBなどの内部状態
- 「このイベントを先に見る必要がある」などの発火条件
- 「正史」「やり込み」「本編目的」など制作・メタゲーム側の分類
- デバッグ上の理由や、なぜこの順序で実装したか

必要な制約はコードで守る。プレイヤーには、扉が開かない、人物が呼び止める、荷物がない、敵が強い、といった体験として現れるべきである。

### 2. 説明できることと、説明すべきことを分ける

設定上説明可能でも、その場で説明する理由がなければ言わせない。

- 見れば分かることをシステム文で再説明しない。
- 戦闘演出で分かる性質を、直後に理屈で解説しない。
- キャラクターが知らないことを客観ナレーションで確定しない。
- プレイヤーが一度疑問を持てる間を残す。

### 3. 沈黙も情報として扱う

文章を置かないことは欠落ではない。

- 全滅後の再開は、画面転換と位置で理解できるなら説明しない。
- 特殊な所持品制限は、メニューを開いた時の状態で分かるなら説明しない。
- 視線、立ち位置、壊れた物、敵の行動先などで示せることは、文章より先にそちらを使う。

### 4. 人間の理解力は均一ではない

登場人物を全員「正しく状況を整理する説明役」にしない。

- 誤解、思い込み、言いよどみ、見落とし、偏見を許す。
- 同じ事件を見ても人物ごとに注目点を変える。
- 感情で判断を誤ることを、直ちにナレーションで訂正しない。
- NPCは攻略情報を渡すためだけに存在させない。

### 5. 想定外をすべて潰さない

進行不能、セーブ破損、意図しない即死などはバグとして防ぐ。
一方、次のようなものはゲーム性になり得る。

- 序盤で勝てない敵に出会う
- 寄り道で想定より強くなる
- 珍しい敵や報酬に早く遭遇する
- 失敗から別の理解を得る
- 一本道に見えていた場所に後から別の意味を見つける

「開発者の想定どおり遊ばせる」ことを目的にしない。
