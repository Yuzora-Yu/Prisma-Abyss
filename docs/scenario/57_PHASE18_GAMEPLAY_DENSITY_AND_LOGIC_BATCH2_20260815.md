# Phase18 探索密度・ゲーム性ロジック Batch2 — 2026-08-15

Status: implemented / new text only for new actors / existing dialogue unchanged

## 1. このバッチの目的

Phase18の町NPC差分を、会話人数の増加だけで終わらせない。
町を歩く理由として、壁際のツボ・タル、固定報酬、再訪で意味が変わる人物を同じ設計単位にする。
後続Phase19で全MAPを拡張・再レイアウトする前提とし、座標を人物・探索物の恒久IDにしない。

## 2. 固定探索物のID方針

- `lootId`: そのツボ／タル／宝箱そのものを識別する安定ID。
- `x / y`: 現在の配置座標。MAP改修時に変更可。
- `legacyPositions`: `lootId`導入前に座標キーで開封済みだった旧セーブを救済する旧座標。
- `openedChests[progressKey]` は `loot:<lootId>` を優先し、ID未設定の旧定義だけ従来の `x,y` を使用する。
- 擬態箱敗北時のrollbackも、取得ID `openKey` と描画座標 `mapPosKey` を分離する。

### 配置原則

ツボ・タルは原則として壁、外周、建物脇へ寄せる。主要通路の中央へ意味なく置かない。
今回追加した6個はすべて現在のマップ配列で上下左右のいずれかが `W` に接している。

## 5. 共通 `EQUIP` ストーリー命令

新規 `EQUIP` action を追加した。

主要引数:
- `eid`
- `plus` (0〜3)
- `fixedOpts`
- `fixedTraits`
- `source`
- `silent`

既存event journalのaction単位保存へ乗るため、装備付与後にアプリが中断しても、再開時に同じ装備actionを二重実行しない。
今回の+3報酬NPCは、`CONV -> EQUIP -> FLAG` の順で一度限りにしている。

## 6. 宝箱実績との分離

従来の固定コンテナ共通処理は、ツボ・タルでも `totalChestsOpened` を増やしていた。
これでは町へ探索物を増やすほど「宝箱ハンター」等の実績を水増しできるため修正した。

- chest: 宝箱開封数へ加算。
- pot / barrel: アイテムは取得できるが宝箱開封数へは加算しない。
