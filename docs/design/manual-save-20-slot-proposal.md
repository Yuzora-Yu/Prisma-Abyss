# 手動セーブ20枠化と全データ入出力

Last updated: 2026-08-14

## 実装状態

2026-08-14、オートセーブ1枠を `localStorage`、手動セーブNo.1～20を `IndexedDB` に置く構成へ更新した。既存No.1～9のキーとレコード形式は変更していないため、データ移行は不要である。

同時に、オートセーブと手動20枠を一つの暗号化ファイルへ出力・読込する機能、復元前の全件チェックサム検査、復元失敗時のロールバックを追加した。Google Drive連携コードも同じ全データ形式を使用し、OAuthクライアントIDが未設定の配布物では無効表示にする。

## 現在の保存構成

- オートセーブ: `localStorage` の `CONST.SAVE_KEY` へ1件保存する。
- 手動セーブNo.1～20: IndexedDB `PRISMA_ABYSS_SAVE_SLOTS` / object store `slots` へ保存する。
- 手動保存前にオートセーブを更新し、そのスナップショットをIndexedDBへ書く。
- 手動保存後は同じレコードを再読込し、チェックサムを照合する。
- 上書き失敗時は直前の手動レコードを復元する。
- 手動枠の読込時は、対象データをオートセーブへコピーしてから再開する。
- オートセーブ単体の暗号化ファイル出力に加え、オート＋手動20枠の全データ出力を利用できる。

## 20枠化で維持する安全条件

1. `MANUAL_SLOT_MAX` を20へ変更し、既存No.1～9のキー・データはそのまま保持する。DB構造変更は不要で、既存セーブ移行も行わない。
2. セーブ画面を開いた時に `navigator.storage.estimate()` が利用できれば、同一オリジン全体の推定使用量と推定上限を取得する。
3. 手動保存前に、保存予定データ量と安全余白を加えた空き容量判定を行う。推定値を取得できない環境では保存を禁止せず、IndexedDB書込結果を正とする。
4. `QuotaExceededError`、IndexedDBのtransaction abort、書込後検証失敗を区別し、「容量不足」「保存領域を利用できない」「保存確認失敗」を利用者へ明示する。「今は利用できないようだ。」だけで終わらせない。
5. 容量不足時も既存レコードを消さず、現在のロールバック処理を維持する。
6. No.1～20をまとめて1ファイルへ出力・復元できるバックアップを追加する。各レコードのpayload、checksum、metadata、slotIdを保持し、復元前に全件を検証する。
7. 永続ストレージ要求と自動復旧スナップショットは、ユーザー方針により今回の実装対象から外す。
8. PCとスマートフォンの通常ブラウザ、PWA相当、プライベートブラウズ、容量不足を模擬した環境で、上書き・失敗・ロールバック・全枠バックアップ復元を継続確認する。

## 容量判断

IndexedDBの上限は固定値ではなく、ブラウザ、端末の空き容量、利用頻度、同一オリジンのCache Storage等によって変わる。`navigator.storage.estimate()` の値も推定値であり、書込成功を保証しない。

このゲームは画像キャッシュも同一オリジンで保持するため、容量推定は手動セーブだけではなくサイト全体の使用量として扱う。推定値が取得できる場合は、保存対象payloadの2倍または1MBの大きい方を直近書込の最低余白として確認する。推定値だけを保存成否の正本にはせず、IndexedDB transaction完了と書込後チェックサム検証を最終判定にする。

## 実装済み項目

1. `MANUAL_SLOT_MAX = 20` と表示文言No.1～20を反映。
2. 保存前の容量推定と、容量不足・保存領域利用不可・書込後検証失敗のメッセージを分離。
3. 全セーブデータの暗号化出力・全件検査・一括復元・失敗時ロールバックを実装。
4. Google Driveへ同じ全データファイルを直接送受信する連携基盤を実装。OAuthクライアントID設定までは無効表示。
5. 既存のオートセーブ単体出力・読込を維持。
