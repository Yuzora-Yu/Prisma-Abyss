# キャラクター歩行グラフィック管理仕様

Last updated: 2026-08-14

## 正本フォルダ

ゲーム内の歩行アニメーションに使用する画像は `assets/characters/walk/` を正本とする。

キャラクター1人につき、下記8枚で構成する。

- `<キャラクターID>_down_1.png`
- `<キャラクターID>_down_2.png`
- `<キャラクターID>_up_1.png`
- `<キャラクターID>_up_2.png`
- `<キャラクターID>_left_1.png`
- `<キャラクターID>_left_2.png`
- `<キャラクターID>_right_1.png`
- `<キャラクターID>_right_2.png`

現在のマップ描画では、各PNGを32×32セルで使用する。通常歩行キャラクターと5年前のアルスは32×32、飛行アルスだけは既存画素を保持するため144×144を正本とし、`assets.js` の `sourceSizeById` で検証寸法を管理する。元素材が長方形の場合も縦横で別々の縮小率を適用せず、等率縮小したキャラクター像を表示セル内に中央・足元基準で配置する。

## IDと時代差分

通常は `characters.js` のキャラクターIDをそのままファイル名に使用する。

同一キャラクターの年代・変身・ストーリー専用姿は、`<キャラクターID>_<差分キー>` を画像参照IDとする。例として、5年前のアルスは `301_past5y` を使用する。セーブデータ上のキャラクターID自体は変更せず、進行状態から参照IDを解決する。

通常のアルスは `301`、飛行中のアルスは状態差分 `301_flying` とする。飛行差分も通常歩行と同じ8フレーム命名を使い、`hero_*` や `hero_wing_*` の専用キー・専用パスは増やさない。

## 歩行と待機

- `idle_down` は歩行アニメーションのフレームに採用しない。
- プレイヤーと隊列キャラクターは、移動入力がない間も現在の向きの `_1` と `_2` を交互に表示し、足踏み待機を続ける。
- `idle_down` 相当の正面棒立ち画像は、村人などと同様に固定配置する場合のみ使用する。
- 固定配置用画像は `assets/characters/map-stand/<キャラクターID>_<向き>.png` で管理する。例: `301_past5y_down.png`。
- 固定配置用画像を `assets/characters/walk/` へ入れたり、歩行8フレームの代用にしたりしない。

## パーティー隊列

- 表示順は戦闘パーティーの編成順 `data.party` を正とする。
- `data.party` のUIDから `data.characters` のキャラクターを解決し、そのキャラクターIDから歩行画像参照IDを決定する。
- マップ上に表示する隊列は最大4人とする。
- 仲間モンスター (`isMonsterAlly === true`) は編成枠を切り詰める前に除外し、人数にも並び順にも数えない。仲間モンスター用の歩行仕様を将来決定するまで、人型キャラクターの画像へフォールバックさせない。
- 飛行中は当面、追従キャラクターを表示せず主人公1人だけを表示する。最大4人の隊列は徒歩移動時の仕様とする。
- 後続キャラクターは先頭が直前までいたマスの座標と向きを受け取り、1マス間隔で前のキャラクターの軌跡を追跡する。曲がり角では履歴に保存された向きを使う。
- 編成順を変更した場合、同じ移動履歴上で新しい編成順を次回描画から適用する。
- マップ遷移、座標ワープ、階層変更、乗り物状態変更では古いマップの履歴を破棄する。遷移直後に同じマスへ重なった後続は、歩行に伴って順番に1マス間隔へ展開する。
- ワールドマップの端を跨ぐ場合は、画面上で最短距離となる側へ後続座標を補正する。
- 飛行中と小舟移動中は主人公／乗り物だけを表示し、徒歩へ戻った時点で隊列履歴を作り直す。
- Phaserを正本とし、旧Canvasにも同じ編成解決・移動履歴・表示順を同期させる。

## 登録とキャッシュ

- 歩行画像を追加したキャラクター参照IDは `assets.js` の `PRISMA_CHARACTER_WALK_IDS` へ追加する。
- 8方向フレームのキーとパスはレジストリから自動生成し、キャラクターごとに8本の手書き登録を増やさない。
- 新規歩行画像は `assets.js` の全量キャッシュ対象に含め、Phaserへのテクスチャ登録と旧Canvasの `GRAPHICS` 参照の両方で同じキーを使う。
- 歩行8枚の不足やファイル名の不一致を、実装時の黙示フォールバックで隠さない。登録時の検証で検出する。
