# 0.2 プレイヤーへ見せる情報と内部実装を分離する【2026-08-10】

ゲーム本文を、内部状態の説明UIとして使わない。

禁止例:

- 「このイベントを先に見る必要がある」
- 「回想中は現在の所持品を使えない」
- 「正史ではない」「やり込みへの祝福」
- 「次の本編目的が解禁された」
- 属性・戦闘ロジックを、演出直後にシステム文で完全解説する

実装原則:

1. 条件はコードで守る。
2. 見れば分かることは文章で重ねない。
3. 状態変化は可能なら配置、敵の行動、画面変化、音、NPCの短い反応で示す。
4. 進行不能・セーブ破損は防ぐが、強敵、寄り道、偶然、プレイヤーの誤解まで均一化しない。
5. validatorは「説明文が存在すること」を正解条件にしない。必要な仕様はデータ・metadata・状態遷移を検証する。
6. 暫定文章でも作業指示を日本語化しただけの文を入れない。
7. キャラクターは均一な理解力を持たない。誤解や感情による判断差を許す。

シナリオ実装前は `docs/scenario/10_PLAYER_INFORMATION_BOUNDARY_20260810.md` も確認すること。

# 3. 実装前に追加したい共通基盤

## 3.1 WorldState / StoryState

NPC・MAP・日記・会話・復興状態を大量に変えるため、booleanの乱造だけでなく意味付き状態を持てる仕組みを推奨。

例：

```js
worldState = {
  fireVillageRecovery: 0,       // 0災害中 1解決直後 2復興中 3終盤
  lunaPublicIdentityKnown: false,
  lunaMemoryStage: 0,
  leonJosephRelationStage: 0,
  hayateZeliedTruthStage: 0,
  churchPoliticalState: 0,
  alanOutcome: 'active' // active / betrayed / dead / saved / rejoined
}
```

既存saveとの互換性を保つため、ロード時のdefault補完／save version migrationを必ず用意する。

## 3.2 NPC条件

最低限区別する：

- キャラを**加入済み**か。
- 現在**同行可能状態**か。
- 現在の**戦闘編成**にいるか。
- 特定真実を**プレイヤーが知った後**か。
- 地域の復興state。

用途：レオン加入後の王国NPC、シャニー同行時の炎の里、ハヤテ＋ゼリード、ルーナ正体判明後の街等。

## 3.3 Flashback / Alternate Scene

新版では別MAP／別キャスト演出の共通基盤自体は必要だが、**光の宮殿内部事件をアルス側攻略中にリアルタイム提示する用途には使わない。**

光宮殿の主要用途は以下。

1. 海底火山後、クロードがルーナを雷の要塞へ連れて来る。
2. アルス／プレイヤーが同時にルーナ生存を知る。
3. ルーナを救護所へ寝かせる。
4. ギルド区画でクロードが記憶を語り始める。
5. 現在MAP／座標／向き／BGM等を退避。
6. 画面へセピア／低彩度等の回想フィルタを適用。
7. 光の宮殿・過去時点へ遷移し、**レイラを操作キャラクターとして開始**。
8. 回想イベントを実行。
9. 元のギルド区画・現在時間へ完全復帰。

共通機能としてはリアルタイムcutawayにも転用可能な設計でよいが、**情報公開順はシナリオ正本を優先**する。

必要機能：

- 現在MAP／座標／向き／BGM／天候／画面フィルタ等の退避・復帰。
- 一時キャラクター／一時パーティ。
- 現在の `progress` を壊さず回想専用のイベントstateを実行。
- 回想内取得物・EXPを通常世界へ持ち出すかを明示的に制御。
- セーブ禁止区間または安全な中断復帰。
- 多重起動防止。

## 3.4 イベント専用ボス

負けイベント・弱体版・プロローグ版が図鑑コンプリートの取り返しのつかない要素にならないよう一般化。

# 4. ルーナ（ID401）専用成長仕様【確定】

## 4.1 基本

- レアリティ：UR。
- 正式加入時の基準値はLv1だが、**光宮殿回想で到達したLv/EXP/装備を最低保証して持ち越す**。現行回想の初期Lvを下回らない。
- UR通常時の基礎経験値要求は元々やや重い。
- さらに加入直後は**必要経験値倍率2000%**。
- 神性が消えたのではなく、ジャスパーの呪縛で成長・出力経路を封じられている。

### 実装注意

「200%ダウン」は数学的な20割減ではない。

**2000% → 1800%** のように「percentage points」を引く。

内部表現例：

```js
luna.expMultiplier = 20.0; // 2000%
```

または整数：

```js
luna.expMultiplierPct = 2000;
```

整数管理の方が安全。

## 4.2 固定イベント

|イベント|EXP|倍率変更|
|---|---:|---:|
|正式加入|—|2000%開始（回想成長持ち越し）|
|結晶樹クリア|+300,000|2000→1800%|
|魔王城クリア|+300,000|1800→1600%|
|火精霊|+300,000|-100pt|
|水精霊|+300,000|-100pt|
|風精霊|+300,000|-100pt|
|雷精霊|+300,000|-100pt|
|光精霊|+300,000|-100pt|
|闇精霊|+300,000|-100pt|
|六精霊完了時|累計+1,800,000|1000%到達|
|アルス×ルーナ連続SQ×5|要調整|最終100%|

六精霊終了時までの固定ストーリーEXP合計：**2,400,000**。

アルス×ルーナ5連続クエストで1000%→100%へ戻す。5段階の個別配分はシナリオ確定時に設定する。

## 4.3 二重取得防止

各イベント報酬は一度だけ。

推奨：

```js
storyRewards.lunaCrystalTree = true;
storyRewards.lunaDemonCastle = true;
storyRewards.lunaSpiritFire = true;
// ...
```

倍率を「現在値から引く」だけにするとイベント二重発火で壊れるため、**イベント完了後の倍率を絶対値でsetする方式も検討**。

例：結晶樹完了後は必ず1800へset。

## 4.4 大量EXP処理

+300,000で複数Lv飛ぶことを前提にする。

- `while (exp >= nextExp)` 相当の反復レベルアップ。
- 飛ばした各Lvの技能習得を漏らさない。
- LvUPポップアップを大量連打しない。
- 上限Lvでoverflowしない。

## 4.5 Lv1スキル

聖女Lv1の治療／浄化／バフを大幅強化する。

意図：

**低Lv＝弱い聖女ではなく、出力を奪われた最上位ヒーラー。**

攻撃・HP・MPは低くてもよいが、治療効率・浄化・耐性バフには明確な価値を持たせる。

# 5. アラン（ID201）状態機械【確定】

## 5.1 推奨状態

```js
alanState = {
  phase: 'joined', // joined / betrayed / boss / dead / saved / rejoined
  equipmentReturned: false,
  appealDocumentObtained: false,
  rejoinExpGranted: false
}
```

## 5.2 海底神殿後

- アラン家旧屋敷で加入。
- 船入手。
- 職：魔法戦士。

## 5.3 光の宮殿裏切り

離脱直前に**全装備を自動返却**。

処理順が重要：

1. 装備をinventoryへ戻す。
2. `equipmentReturned=true`。
3. パーティ／加入可能リストから離脱。
4. `phase='betrayed'`。

再ロード・イベント再入場で二重返却しない。

## 5.4 ハヤテ連続クエスト

- ゼリード起点。
- アラン父の汚名を雪ぐ。
- ハヤテ父・ゼリードの過去へ繋がる。
- 終盤にハヤテ加入。
- 完遂報酬キーアイテム：**王への上申書**。

`王への上申書` はアラン救済ルート必須。

## 5.5 統合の祭壇・戦闘前

### 上申書あり

通常通り戦闘へ。
戦闘後に生存／救済ルートを使用可能。

### 上申書なし

専用会話を必ず実行：

- ジョセフ
- レオン
- クロード
- レイラ
- ゼリード

の苦悩を強める。

ガイル／サラにも「本当にこのまま倒していいのか」「仲間だった」という趣旨を言わせる。

その後：

```text
進む
引き返す
```

を提示。

**引き返す：** MAPを戻り、救済条件を探せる。  
**進む：** アラン戦。撃破後死亡確定。

これは意図的な不可逆要素。勝利後に「やっぱり助ける」は不可。

## 5.6 アラン死亡

```js
alanState.phase = 'dead'
```

以後：

- 再加入不可。
- 蘇生不可。
- 上申書新規取得不可。
- 未発生／未完了のハヤテ加入関連クエストは発生不可または失敗状態へ。
- NPC／エンディング／アーカイブ差分。

セーブデータ上で永久保持する。

## 5.7 アラン救済／再加入

上申書所持＋救済ルート選択後：

- `phase='saved'` 相当の生存状態を保持。
- 災禍の根ジャゴレアでジャスパー撃破後、正式再加入をプレイヤーが再選択。
- 実加入時の内部経験値：**+1,000,000**を一度だけ付与（`alan_jagorea_join_1000k`）。
- 光魔剣士への職変更構想は維持するが、職定義／成長／習得技の確定が必要なためPhase8F runtimeでは未実装。
- `alanRejoinedAfterJasper` で正式再加入を保持。

光魔剣士用に最低限必要：

# 15. v3 実装差分 — 光の宮殿・プレイアブル回想

## 15.1 Scene Context要件
回想は現在世界から隔離した一時ゲーム空間として扱う。

- 現在のMAP／座標／向き／パーティ／キャラクター／所持品／装備袋／所持金／図鑑等をsnapshot。
- `visualPreset: sepia`。
- 回想中の通常saveは抑止。
- 回想専用 `items` / `inventory` を使用し、アルス側所持品を参照禁止。
- 回想中に開けた宝箱は終了時に現在側へ開封済みとして統合し、二重取得を避ける。
- 回想で拾った消耗品・未装備品は現在側へ統合。
- 装備中のもの、Lv、現在Lv内EXP、追加習得技は人物carryoverへ格納。
- 後の `addStoryAlly()` 時にcarryoverを適用。

## 15.2 チェックポイント
- checkpoint `saint_room`: レイラ＋ルーナ、聖女の部屋。第一逃走区間全滅時に復帰。
- checkpoint `post_veld`: レイラ＋レオン＋クロード、フラッシュボム直後。第二逃走区間全滅時に復帰。
- 通常エンカウント全滅でも通常GAME OVERのワールド復帰処理を行わず、該当checkpointへ戻す。

## 15.3 六芒星の罠
仮MAPでは3階の必須通過座標へ非表示 `storyEvent` tile effectを置く。最終図面反映時に六芒星の間の正式座標へ移設する。

処理順:
1. ジャスパー罠。
